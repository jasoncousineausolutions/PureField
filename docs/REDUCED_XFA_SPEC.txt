REDUCED XFA SPEC
Client-side flattening of legacy Adobe XFA PDFs

Audience: open-source JavaScript developers building browser utilities that turn legacy XFA forms into ordinary, readable PDFs.

This spec keeps only what a client needs to extract layout, bind data, and paint a static page. It drops LiveCycle connections, external fragment fetches, and server-side mutation. Scripts run only as far as §11 allows: the load and print events, on a sandboxed object model. The output is page content, not a live form.

The pipeline is closed. Extraction yields the template and the data root. Binding builds an instance tree. Picture clauses produce display strings. Flow places boxes. Chrome and draws paint those boxes. Measurement wraps text. Static files keep the shell page and overlay text. Dynamic files synthesize pages. The Y axis flips once, at page seal.


1. Packet extraction

Resolve Catalog, then AcroForm, then the XFA entry. If XFA is missing, the file is not XFA. The entry is either one stream holding a full XDP document, or an array of name/stream pairs. Streams are usually FlateDecode. In the array form, even indexes are names and odd indexes are streams. An odd-length array is malformed; do not guess the pairing.

Parse every packet the same way whichever XML parser the platform has. Line ends are normalised as XML 1.1 normalises them: CR LF, CR, NEL, U+2028 and U+2029 all become LF. A browser parses as XML 1.0 and would keep a U+2029, but Reader breaks the line there, as in the footers of Stammdatenaenderung and the dclUnica forms. A stray "&" that starts no reference is text to Reader: ircc-imm1344e-filled's data has "Humanitarian & Compassionate". When it makes a packet ill-formed, parse the packet again with it escaped; CDATA sections and comments stay as they are.

Normalize names before use. template stays template. datasets, dataSets, and data all become datasets. localeSet and localeset become localeSet. Match namespaces by prefix, not full URI: xfa-template, xfa-data, xci, xfa-locale-set, and the XDP envelope at http://ns.adobe.com/xdp/.

Keep template. It is required; without it, abort. Prototype references are resolved before the template is read (pdf.js $resolvePrototypes): an element with use="#id" or a SOM use, or usehref "#id", ".#som(expr)" or "#som(expr)", inherits from the element of the same kind that it names the attributes it does not set, its text when it has none, each single property (font, para, margin, border, value, ui, …) merged with its own or copied, and repeatable children (edges, corners, items, events, containers) beyond its own; <proto> and nameless containers are transparent to the SOM; cycles break and references to other documents stay unresolved (XFA_USE_SKIPPED). Designer stylesheets work this way: echr-application-es takes its Calibri fonts and grey field borders from designer__stylesheet. A template that is present but unusable (not well-formed, or with no root subform) is a form Reader cannot render either: print the PDF's own pages, blank or not (itext-empty-xfa's empty <template/>; pdfium-rectangles-multipage, whose template packet is a whole second XDP document with its own XML declaration). Keep datasets for values; if it is missing, render template defaults. Keep localeSet only for symbols actually used by picture clauses, falling back to en_US. Keep a thin slice of config: PDF version, the dynamicRender flag, and whether the form was interactive. A form packet, if present, is a cache, not a source; datasets wins when they disagree. With restoreState auto it is the best record of what the form's scripts did, so its presence, relevant, x, y, w and h, unbound values and draw and caption texts replace the template's (imm1294e's office-use box, grown by a script to 1.307in, prints at that height in Reader). Preamble and postamble are framing only.

Discard connectionSet, sourceSet, xdc, stylesheet, xslt, signature, xfdf, the pdf packet, xmpmeta, and unknown packets. Log the names. Do not fail. Do not resolve usehref, fragment URIs, or connection endpoints.

The data root is the first element child of xfa:data that is not in the XFA data namespace; an xfa:data nested in another is looked through (itext-dataset-2page). dataDescription is ignored. Application XML under xfa:data is the instance document. Repeated sibling elements are occurrence data, not extra packets.

Config is reduced to two facts. dynamicRender of required means the template must be reflowed; scripts run either way (§11). External locale URIs are forbidden.

Corrupt template aborts. A corrupt localeSet degrades to en_US. Duplicate canonical packets keep the last one.


2. Coordinates and units

Store resolved measurements as PDF points, origin at the top-left of the current container, X to the right, Y down. A box is x, y, w, h of the margin box. PDF user space is bottom-left, Y up, same point unit. Convert to that frame only when a page is sealed.

A measurement is an optional sign, a number, and an optional suffix stuck to the number. A bare number is inches per the Adobe XFA spec (pdf.js treats it as points; Designer almost always writes a unit, so this rarely matters). Zero needs no unit. in times 72. cm times 72/2.54. mm times 72/25.4. pt is identity. pc times 12. mp times 0.001. Use the rational form. An unknown suffix yields 0 and a log; px is not an XFA unit. Angles are degrees counterclockwise from the positive X axis. Honor 0, 90, 180, and 270; round anything else to the nearest quarter turn.

Percent and em cannot be resolved at parse time. Percent is of the parent content width for w and x, and of the parent content height for h and y. em is the element font size, fallback 10pt.

Page size comes from pageArea/medium. short and long win. Otherwise map stock: letter 612 by 792, legal 612 by 1008, tabloid 792 by 1224, A4 595.2756 by 841.8898, A3 841.8898 by 1190.5512, A5 419.5276 by 595.2756. landscape swaps the edges. A missing orientation keeps short as width. contentArea is the inset origin for the root subform. Extra content areas are spill regions in document order. Overflow leaders are not implemented.

Child x and y are offsets from the parent content origin, after margin inset. anchorType names which point of the child sits on that coordinate; default is top left. x and y apply only when the parent layout is position. In flowed layouts (tb, lr-tb, rl-tb, row, table) they are ignored; spacing comes from margin and para spaceAbove/spaceBelow.

At seal, with H the page height: llx = x, urx = x + w, lly = H - (y + h), ury = H - y. Rotate about the anchor in XFA space before the seal. Swap w and h after 90 and 270 so the PDF rectangle still encloses the object. Text baseline is not the box top.


A property an object may have once (ui, caption, value, format, font, para, margin, border, bind, keep, occur, overflow, calculate, validate, assist, traversal) keeps its first occurrence; a later duplicate is ignored, as Reader ignores it (anaf-d017's section headings carry a stale second <value> and <font>).


3. Container flow

Layout reads the expanded instance tree, not the template prototype. Names do not affect placement.

Subform is the general container. Area is a geometric group and does not bind. subformSet is not a box; its instances join the parent flow in document order. exclGroup is a box around its fields. field and draw are leaves. pageArea is not flowed; its content areas receive spill.

Presence is applied before placement. visible paints and consumes a slot. invisible consumes a slot and does not paint, and nothing inside an invisible container paints either (imm1294e's invisible North-American phone subform). hidden and inactive do neither (inactive is hidden plus excluded from events).

relevant filters by view. A flattener is the print view: a node whose relevant list contains -print, or names only other views (for example +screen), is not printed, nor is anything inside it. It still takes its space, like invisible: Acrobat lays the form out once for screen and print (the Romanian D212 forms' -print buttons and help icons push the page down by exactly their heights in the Reader prints, 17pt on dclUnica, 31pt on declaratieUnica). This is how buttons and on-screen instructions are removed; do not skip nodes by name.

Children place inside the content box, after margins. minW, minH, maxW and maxH of a subform do not bind, in any layout: the content decides (Acrobat prints Conflict-of-interest's minH 178mm tb section and imm1294e's minH 23.8mm positioned education row at their content height; pdf.js applies them as CSS inside a position parent). A field or draw honours them in every layout (pdf.js Field/Draw layout; Acrobat prints a minH multi-line field in an lr-tb subform at minH). An omitted w or h is indefinite. Flow closes it from children. position does not. min and max clamp the closed size. Layout does not clip.

Default layout is position. Unknown values fall back to position.

position places each child at its x, y. Siblings do not move each other. Document order is paint order, later on top. A declared h wins; an omitted h grows to the lowest child bottom (same for w and the rightmost child edge). A hidden field with a declared h counts toward that bottom by its y + h, though it is neither laid out nor painted; growable hidden fields and hidden draws do not (on-1965e's hidden 5.08mm frmInt field makes its header 3pt taller in Reader; on-fw1015e's hidden minH field and hmrc-c1800-chief's hidden help lines add nothing).

tb stacks top to bottom. Omitted child width becomes the content width for subforms and draws; a field with no w keeps its natural width (caption plus widget), clamped by minW and maxW and capped at the content width (pdf.js Field layout; Acrobat prints ALTMP's minW button at minW, not across the page). Omitted child height is the child's closed height, or the font box for a leaf. A text value's natural width includes its para marginLeft and marginRight, which narrow its lines (mn-dhs-4258a's 1pt-indented headings stay on one line). Parent height is the cursor plus bottom margin.

lr-tb packs left to right and wraps when the next child does not fit. Row height is the tallest child on the row. justify inserts gaps; it does not stretch children. A child wider than the row sits alone and may overflow. rl-tb is the same from the right edge.

table reads columnWidths, a space-separated list of measurements or -1. Missing entries are -1, meaning the natural width of the widest cell in that column that does not span. Lay cells out at natural size, set column widths, stretch cells horizontally, set row height to the tallest cell (a stretched cell's value area grows with it, so its vAlign applies to the full row height; Selbstauskunft's "lfd. Nr." headers print centred), then stack rows. There is no row span. colSpan of -1 consumes the rest of the row and drops later siblings. A column whose every cell spans is undefined; split the remaining width and log it. Children that are not rows flow after the table at full width. A table with no w whose columnWidths are all given is as wide as its columns, not its parent, so its border boxes them alone (ro-pos-cce-application's 102mm + 30mm co-financing table, anaf-d101).

occur is already resolved by binding. Layout must not drop an empty instance.

A child that does not fit the remaining content area moves to the next content area, then the next page area. A leaf taller than a content area is placed anyway, except text: a text draw or multi-line text field (vAlign top, caption on top or none, not rotated) that does not fit, or whose fixed h is taller than a content area, is cut between lines; the lines that fit stay with the caption, the rest continue at the top of the next areas, as many as they need, the last keeping what is left of the box's minH or h (anaf-d1000's 457mm article draw runs over two pages in Reader). A piece's lines are painted at the full pitch, so the cut is made where they fit counting its first line at the full line height, not at the font size a box is sized by (anaf-d1000's page 3 ends on its 46th line, "ART. 4", as in Reader). A field box taller than its text (a minH or h beyond its lines) is cut anywhere below the text: its first piece, caption included, fills the area and the blank rest carries on (on-a-103e's empty explanation boxes run from page 4 onto page 5 in Reader). Its first line, or for a captioned field its caption, with the margins, is what must fit before its container starts on a page; a row of an lr-tb subform holding only such a leaf splits the same way. An empty field, with or without a caption and whatever its vertical alignment, is such a box; its one empty line stays in the first piece, so a middle-aligned empty field is cut only when the room left reaches past its middle (half its height and a line), and a bottom-aligned one is not cut. A table row whose cells are all such empty fields is cut the same way, its row box and each cell in two pieces (ro-pos-cce-application's 2.3.3 justification box runs from page 13 onto page 14 in Reader, while its 2.3.2 context box, with 41pt left, moves on whole). A flowed subform that is split keeps its top margin with its first piece: when the margin and the first row (lr-tb) or the first child's first piece (tb) do not fit, the whole subform starts in the next area instead of leaving a margin-only fragment behind. A positioned subform or area with no h that does not fit (and is not keep intact) breaks at the highest horizontal line no child crosses: the children above it stay, the rest move up to the top of the next area; if every line is crossed it moves whole (Acrobat prints of dclUnica 2023 break the SECȚIUNEA I.3 area between its rows; pdf.js never splits a position layout). Each continuation of a split subform starts with its top margin again (dclUnica's bife section, topInset 5mm, resumes 5mm down page 2 in the Reader prints). Each piece of a split subform ends with its bottom margin, so every row or child placed inside subforms being split must fit together with the bottom margins of all of them, as the area may end after it; otherwise it moves on and the margins follow it (Acrobat prints of imm5707e: the NOTE 1 and NOTE 2 boxes break as Reader breaks them; anaf-d017: the C.b period row, which fits only in the 6mm its three sections' bottom insets need, starts page 2). Honor breakBefore and breakAfter of pageArea. A pageArea break that names a target, without startNew="1", starts no page when the page is already of that page area (ro-pos-cce-application's budget table, breakBefore Page1 inside a section whose own break has startNew="1", starts under the co-financing table on the section's first page in Reader). When a split subform runs out of page, the new page uses the page area named by the overflow target (overflow@target, or the legacy break@overflowTarget) of the innermost subform being split, if any (a registration form's page1 subform continues on Page2, which has no copyright or "Disponible en français" footer, as Reader prints it). When the flow overflows (not at an explicit break), the container whose overflow element governs is the innermost one holding the object being moved on, among the subforms being split and the subform sets dissolved into them: if that overflow names a leader, a copy of the leader is placed at the top of the new area, after the continuation's top margins, once the leader has been placed in the flow itself (a table's header row, overflow@leader or break@overflowLeader: "#id", or the nearest descendant of the container with that name, the last part of a SOM path; unresolved ones are logged as XFA_OVERFLOW_UNRESOLVED). The copy is the same laid-out node, at its own x in the container, with its cells; it binds nothing and runs no script. An overflow element that names no leader repeats nothing, even inside a table that has one: ro-pos-cce-application's budget sections are subform sets with overflow target="Page1" inside its HeaderRow_buget table, and Reader's continuation pages carry no header. A leader taller than the area is left out (XFA_OVERFLOW_LEADER). The trailer the same overflow names keeps its height free at the bottom of each area the container continues from, and is placed there (at the area's bottom, not under the last row) when the flow leaves the area; the container's last child reserves nothing, so the trailer in the flow ends the last piece, and a trailer with no room left is left out (XFA_OVERFLOW_TRAILER). Bookends are ignored. Of the sample forms only ro-pos-cce-application continues a container whose overflow names a leader in this layout (CIE-XFA-work's and the dclUnica tables fit their pages; Anexa_D212 and D_212 are static), so the leader and trailer rules are checked against Reader on that form only. keep intact moves a subform to the next region if it fits; otherwise place it and log. keep next (or the following sibling's keep previous) of contentArea or pageArea moves a node that would fit to the next region when its neighbour's first piece would not fit after it, so a heading travels with its section (imm1294e SIGNATURE heading). Between the rows of an lr-tb subform the keeps chain: a heading row kept with a text row kept with a field row moves on unless the rows and the last one's first piece fit (mn-dhs-4258a's Substitute caregivers section). A contentArea break with a target goes to that content area of the current page while nothing has been placed there yet, else to it on a new page; startNew="1" starts a new instance even when the flow is already in it. A contentArea target on another page area ("Page3.ContentArea3") starts a page of that page area, or turns a still-empty page into one (da-form-5575, da-form-638 and da-form-3508 print their instructions on their own page area, without the continuation header). A positioned container breaks at the highest line no child crosses when it has no h, or when its keep intact is explicitly none (Designer's "allow page breaks within content"), and so does a table row whose cells are such containers; the height of its first piece is what must fit before its table or parent starts on a page (tx-appellate-docketing's 139.7mm section XII, a table row, starts under section XI and runs on to the next page, as in Reader). A container with a page or content-area break among its flowed descendants is flowed piece by piece even when it fits, so the break happens (on-a-103e's submit section starts page 9, as in Reader). Nothing of zero height overflows, even after content that already overran the area (eu-mir-7-2-1's empty last subform makes no page). A break to the area the flow is in does nothing (hmrc-c1800-chief fills its banner, menu and main content areas by such breaks; itext-dataset-2page starts its second product on a new page). Overflow to a container's overflow target that names a content area follows the same rule; without a target, the flow takes the next content area not yet used, then a new page. Breaks of hidden containers do not move the flow (da-form-638's hidden pages and imm1294e's hidden Page5 make no pages in Reader).

This stage emits placed nodes in top-left page points. It does not flip Y.


A pageSet whose relation is simplexPaginated or duplexPaginated, and some of whose page areas set pagePosition or oddOrEven, chooses each new page's area (where no break names one) among its page areas: pagePosition first fits the set's first page, rest the pages after it, any every page; for duplexPaginated, oddOrEven odd or even must fit the page number; an exact fit beats any. Once the pages are known, the set's last page takes its page area marked last (only, for a set of one page, else last) when the page's content fits that area's first content area: the content moves with the content area's origin; otherwise it keeps its area (XFA_LAST_PAGE_AREA). blankOrNotBlank is ignored. Other page sets follow document order and occur.

A container's bookend (leader, trailer: "#id" or a name) moves the child it names to the start, and the trailer's to the end, of the container's flow, once; a name that is not one of its children is ignored.


4. Typography

Text is painted after boxes are sealed. The string is the display string, already formatted. Inheritance walks parent subforms, but only for a node with no font element: a font element is complete, and its omitted attributes take the defaults (Courier, 10pt, normal weight and posture) rather than the parent's values, as pdf.js does, and a font with no fill is black (pdf.js lets CSS inherit the colour, but Acrobat prints a registration form's captions and dclUnica's "Semnatura electronica" black under blue field fonts). A caption with a font element that names only a typeface is therefore 10pt and black, not the field's size and colour. A missing font is Courier at 10pt, normal weight, normal posture, not Myriad Pro.

typeface maps through an embedded shell font, then a standard face, then a substitute, then Courier. Myriad Pro, Myriad, and Adobe Clean become Helvetica; when Unicode TrueType faces are embedded, Myriad text is drawn at Myriad Pro advance widths (pdf.js's Myriad tables, in the run's weight and posture: italic Myriad is about 5% narrower; a letter with a cedilla or comma below, ş ţ ș ț ģ ķ ļ ņ ŗ and their capitals, as wide as its base letter, where pdf.js's tables fall back to Helvetica's widths), so line breaks follow Myriad (anaf-d1000's article 2.5 keeps "din" on its first line, as Reader prints it). When the PDF's AcroForm default resources (/DR /Font) declare the requested family (FontDescriptor FontFamily, weight 700 = bold, non-zero ItalicAngle = italic), Helvetica-class text is measured with that font's /Widths and drawn at those advances; pdf.js (loadXfaFonts) and Acrobat lay text out with the same widths, and narrow faces such as Source Sans Pro or Calibri then wrap as in the Acrobat prints. Text with known widths (declared, or Myriad) is drawn with the bundled glyph set that fits them best: of Liberation Sans and Source Sans Pro in the requested style, the one whose letter and digit widths have the smallest spread of ratios to the known widths (RMS of log ratios about their median), horizontally scaled by that median when it differs by more than 5%; a run with a character the best set lacks uses the next set that covers it, Liberation Sans last. Source Sans Pro fits Myriad, Calibri and itself (rms 0.06, 0.08, 0) far better than Liberation Sans (0.10, 0.12, 0.10), and Reader prints Myriad with its own bundled Myriad Pro, so this follows Acrobat rather than pdf.js (which draws Liberation Sans). Squeezed Liberation glyphs at Source Sans widths overran the narrow spaces ("Coordonnéesdu" on CIE-XFA-work). Each substitute glyph is centred in its slot (the known advance): it is shifted right by half the difference between the slot and its own scaled advance, so a glyph narrower than the face it stands in for leaves no hole after it and a wider one spreads evenly into both neighbours (Myriad Pro Bold M is 846 units, Source Sans Pro Bold's 762: "ICM JE" before, "ICMJE" as Reader prints it on Conflict-of-interest). When the declared font embeds a TrueType program (FontFile2), its own glyphs are drawn at the declared widths, for any face, as long as it covers the run (a symbolic (3,0) or Mac (1,0) cmap is addressed by the WinAnsi code); that is how a barcode face such as Free 3 of 9 prints as bars. A no-break space a face does not list advances like its space. Arial becomes Helvetica. Times New Roman and Minion Pro become Times-Roman; when the form declares the serif face's widths, its text is measured with them and each run of the standard Times is horizontally scaled to their total (Attestation's Minion Pro lines then span what Reader's Minion Pro does, within 0.2pt). Courier New stays Courier. The standard Times and Courier faces also draw the Latin Extended-A letters the Core 14 fonts carry (ă ș ț ş ţ, Polish, Czech, Hungarian, Baltic letters…), as wide as their base letter, through a WinAnsi encoding with /Differences that gives each letter drawn one of the codes WinAnsi leaves empty (37 per document), so Romanian Times New Roman text keeps its serif as in Reader (anaf-d104's "Se completează"). Anything else is Helvetica, logged once. Wingdings and Symbol text holds font codes, as U+F020–U+F0FF (a symbol cmap's private-use block) or as the bytes themselves; each code is drawn as the Unicode character it stands for (Wingdings 0xFC is ✓, 0x6F □, 0x6C ●; Symbol letters are Greek), so campania-scia-it's Wingdings check marks print as in Reader. A character the chosen bundled face lacks is drawn with the other bundled face when it has the whole run (Source Sans has ✓ ☐ ☑, Liberation Sans does not). A face that ends up drawing only .notdef is still embedded, so no page names an undefined font. Other writing systems, in XFA and AcroForm text alike: characters no Latin face has are drawn, run by run, with DejaVu Sans (Arabic, Hebrew where Liberation Sans lacks it, Armenian, Georgian), loaded only when the form's text holds them, Arabic at 0.85 of the font size and 90% wide, as Reader's Arial Arabic measures against DejaVu's (pdf.js's freetext_no_appearance: Reader's lines are 0.73–0.79 of DejaVu's width at the same size and about 0.85 of its height, so its eleven lines fit the box unwrapped); CJK characters with Adobe's standard CJK fonts, not embedded, addressed through the collection's Unicode CMap (Japan1 KozGoPr6N-Medium with UniJIS-UTF16-H when the text has kana, Korea1 AdobeGothicStd-Medium with UniKS-UTF16-H when it has Hangul, else GB1 AdobeHeitiStd-Regular with UniGB-UTF16-H), each a full em wide, or with a CJK TrueType font supplied as CJK, embedded. Arabic letters are measured and drawn in their joined forms (Presentation Forms A and B: initial, medial, final, isolated, lam-alef ligatures, harakat transparent to joining), and each drawn line is put in display order: right-to-left letters reversed, numbers left to right inside them, neutrals taking the direction of the strong characters around them when both agree and the paragraph's otherwise (the paragraph's direction is that of its first strong character), brackets mirrored in right-to-left runs. Alignment stays as set (/Q, hAlign). Bold and italic select the standard variant. A missing variant is synthesized.

size is a measurement. fontHorizontalScale and fontVerticalScale are percentages, default 100, and are the exception to the inch rule. They scale the text matrix; they do not rewrite the string. Width for wrapping uses horizontal scale. A scale of 0 paints nothing. Scales outside 1 to 1000 clamp. baselineShift is text rise. letterSpacing becomes character spacing in text space, spacing divided by size. Color is r,g,b from 0 to 255. Missing fill is black. Spot and ICC colors paint black.

para does not change the field box. hAlign default left; justify only on wrapped lines: every line but a paragraph's last is spread to the full width by widening its spaces (justifyAll spreads every line; Acrobat prints); radix aligns on the locale decimal and falls back to right. vAlign default top. lineHeight default is 1.2 times font size. Lines are spaced by lineHeight, but the text block runs from the first line's ascent to the last line's descent: top-aligned text has its first baseline one ascent below the top, bottom-aligned text its last baseline one descent above the bottom, and middle centres that block (no half-leading; measured on the Acrobat prints of eight sample forms). Ascent and descent are the face's typographic metrics: Arial/Helvetica 0.728/0.210, Myriad Pro, Source Sans Pro and Calibri 0.75/0.25. textIndent applies to the first line; a negative one indents the lines after it instead (see Rich text). A growable field, draw or caption is sized the same way, rich text included: n lines of text are the font size (times vertical scale) for the first line plus lineHeight for each further line (pdf.js TextMeasure firstLineHeight; Acrobat prints of dclUnica, Attestation, Selbstauskunft, evince and a registration form agree, and the old n × lineHeight made every one-line field 0.2em too tall; for rich text a registration form print settles it, 2pt per paragraph). With a set para lineHeight the first line counts as that height or the face's own line height, whichever is less (Arial and Liberation Sans 1.149em, Times 1.15em, Courier 1.133em, Myriad-class 1.2em): on-a-103e's two-line 18.75pt bullets in 10pt Arial are 40.8pt apart in Reader, hmrc-iform's one-line 11.5pt bullets 14.3pt, and on-5026-41f's 14pt title lines in 14pt bold Arial stay 14pt. Painting keeps the full pitch: every rich line, the first included, is painted in a full lineHeight with its half-leading (ALTMP's multi-paragraph notes keep their Reader positions), so only the size the text claims loses the first line's gap. Overflow clips at the box sides; vertically the clip has 0.3em of headroom above and below, since accents on capitals and descenders reach past the ascent/descent box text is placed by and Reader does not cut them off (Stammdatenaenderung's "Änderungen"). A single-line field does not wrap. Plain text keeps its leading spaces on its first line (anaf-d093's space-indented captions print indented in Reader). Plain text holding tabs is set as rich text, so each tab advances to the next para tab stop (every tabDefault, 0.5in by default), as Reader sets tx-appellate-docketing's tabbed lines; a tab in caption text is a space (never a .notdef box: on-1965e's footer ends in a tab). Empty text (an empty field, a draw with empty text or no value) holds one line without its gap, that is the font size times vertical scale (pdf.js lineNoGap; Acrobat prints of Selbstauskunft's empty separator draws, which set the table row height, and of Attestation's empty fields). A middle-aligned caption is centred between the field's top inset and its outer bottom edge: the field's bottom inset does not count (the itext and pdfium sample fields' 1mm insets put their captions 1.4pt lower in Reader; dclUnica and declaratieUnica agree). A check box's caption is centred inside both insets: declaratieUnica's i13 (insets 1mm and 5mm) prints its caption 6pt above the label beside it, and its 1mm-inset rows centre their captions on the box within 0.3pt. The value text is centred inside both insets as before (the same change there lost on ALTMP and Attestation). Caption text uses the caption font, else the field font, and wraps inside its reserve less the caption para's marginLeft and marginRight, as a value does (dclUnica's 14.173pt-indented check-box captions wrap "forfetare / de cheltuieli" as Reader prints them); an automatic reserve includes those margins.

Rich text is the exData text/html subset: p, b, i, span, br, and a short CSS set (family, size, weight, style, color, decoration, align, tab-stops, vertical-align). vertical-align is super, sub or a length to raise the run by (Selbstauskunft's m<span style="vertical-align:2pt">2</span> prints as m²); on a paragraph (p, div, li, h1–h3) a length instead makes each of its lines that much taller, the room above the text, which is not moved within its line (dclUnica's closing statements, <p style="vertical-align:3pt">, are 17.4pt apart in Reader, and a blank paragraph so styled before them puts them 3pt lower), and super or sub there does nothing; and a raised run that reaches above its line's ascent makes the line taller by as much, room taken above the text as in a CSS line box (anaf-d1000's "CIF²" lines stand 2.6pt lower in Reader); as in CSS it does nothing on a block, except baseline, which sets the font's baselineShift back to 0 for what it holds. A rich line in a font with a baselineShift is taller by the shift (anaf-d092's draws in a 7pt-shifted font: their 11pt lines are 20.2pt apart in Reader, the closing paragraph set back on the baseline 13.2pt). Unitless font-size inside rich text is points. A br that ends a block opens no new line; a block holding only a br is one empty line. xfa-spacerun keeps every space, and spaces stay break opportunities, a no-break space written inside the span included (Acrobat breaks imm5707e's "the<spacerun>&#160;</spacerun>Access" there). Lines break only at spaces, across style runs too: an italic word and the full stop after it are one word (evince's "Privacy Act."). Trailing spaces, no-break ones included, hang past the line end: they neither push their word to the next line nor count for alignment (dclUnica's "SUBSECȚIUNEA I.1.1&#160;" labels stay on one line; Acrobat centres the 2025 title without its trailing space). A negative text-indent (CSS or para) never outdents the first line, which starts at the left margin; it indents the paragraph's later lines by as much instead (evince's margin-left:13.5pt; text-indent:-18pt bullets start at the margin; a registration form's textIndent="-18pt" bullets wrap under the text after the bullet, and declaratieUnica's textIndent="-65pt" heading wraps 63pt in, as Reader prints them). A floating field (span xfa:embed) is measured as the text it will show: the referenced field's value, or for a page-number field as many digits as the page count (a layout that reaches ten pages is redone with two), so imm1294e's "PAGE 1 OF 5" fits its box as in Reader. xfa-tab-count advances to the next tab stop (CSS tab-stops, else para tabStops, else every tabDefault, 0.5in by default), measured from the paragraph's left edge (Acrobat prints of tabbed footers). A tab whose stop lies past the right edge wraps the line, and a wrapped line drops its leading tabs and spacerun whitespace; whitespace that wraps past a paragraph's last word opens no line (Conflict-of-interest's tab-padded Definitions: "Licensed:" starts its own line at the margin, as Reader prints it). Scripts and images are stripped. A link (a with href) keeps its text and is painted blue (0,0,255) and underlined unless its own CSS sets colour or text-decoration (Acrobat prints of evince, imm1294e, Conflict-of-interest, Purchase.Order). A list item (li in ul or ol) is a paragraph indented 36pt a level, its marker hanging half an em left of its first line: a bullet for disc (circle, square likewise), "1." for decimal, "a."/"A." for alpha and "i."/"I." for roman list-style-type (mn-dhs-4258a's "I agree that:" bullets, as Reader prints them). A paragraph's CSS margin-left and margin-right replace the para's marginLeft and marginRight, as its text-indent replaces the para's textIndent (anaf-d1000's "1.2.2." caption, margin-left:28.346pt under a 28.346pt para marginLeft, starts where its plain-text siblings do). The para's spaceAbove and spaceBelow apply between the paragraphs of rich text as well as around the whole text, except where a paragraph sets its own margin-top or margin-bottom (mn-dhs-4258a's and tx-hhs-h1805's spaceBelow open gaps after each p in Reader; on-11075e's margin-bottom:0pt address lines stay tight). The first paragraph's margin-top and the last's margin-bottom collapse with the para's spaceAbove and spaceBelow, as CSS margins do: only what exceeds them is added (on-4871-64f's margin-bottom:10pt paragraph in a spaceBelow="10pt" draw leaves 10pt under it, not 20pt).

Runs are emitted in PDF user space. Horizontal and vertical scale stay fractions on the text matrix and are not baked into size.


5. Binding

Layout never reads xfa:data. Binding merges the template with the data root and emits the instance tree. It does not format values.

Default match is once: the first unbound child of the current data node with the same local name. dataRef resolves the ref SOM and need not be a direct child. global takes the first unbound node of that name anywhere under the data root. none consumes nothing and keeps the template default. Name compare is local-name, case-sensitive, namespace-insensitive. Attributes are not candidates except through a dataRef tail of @name. A dangling ref binds nothing and does not fall back to name match. $.a.b is relative to the current data node. An unqualified a.b first looks under the current data node, then under each ancestor in turn (SOM implicit scoping, as pdf.js does). $record and xfa.datasets.data are absolute from the data root. An unqualified ref starting record. that finds nothing by scoping is read as $record. (Acrobat prints the Selbstauskunft totals and comment rows bound that way).

Each subform that binds a data element pushes it as the current node for its children. A subform that finds no data still pushes a synthetic empty node if it is instantiated. match none does not push, so children bind against the parent node. area never binds. exclGroup binds one value; its members do not each consume a node. subformSet does not bind.

Occurrence is applied before the children walk. Count unbound matching siblings, then clamp to min and max. max of -1 means no ceiling. Omitted min is 1 (0 only for pageArea and pageSet). Omitted max equals min when min is given, else 1 (else -1 for pageArea and pageSet). A max below min is raised to min. An omitted max is never below initial, so the common Designer pattern min="0" initial="1" yields max 1. Omitted initial is 1 for the root subform, else min. Instances past the data count get an empty node. A subform with match none (or no name) consumes no data and is instantiated at least once, even with min 0 (pdf.js; Acrobat's saved form state agrees). initial matters only when the whole record is absent; then each subform gets initial instances. (pdf.js instead drops min="0" subforms on an empty merge; this spec follows the XFA meaning of initial.) Empty instances are real.

A field raw value is the direct text of the bound element. Descendant element text is ignored. A failed match uses the template value, then empty. A bound empty element is empty and does not use the template default. xsi:nil stores null. Choice lists bind the save value. Checks bind the raw on-value. Picture clauses do not run here. A numeric field with no display picture and no decimal value type shows its number without trailing zeros (itext-dataset-2page's "2.00000000" prints as 2). A value that would only have come from a script uses the template default and is logged; §11 then runs the script. Page-area content binds only through explicit dataRef or global binds (match once would take data meant for the body); a page-area subform with a dataRef bind moves the data node its children's refs are relative to (Attestation's footer subform FrgBoutons binds $.FrgBoutons and its btnvis field $.btnvis under it, so the field reads the data's 1, not its template 0).

Output is the instance tree plus raw string or null, a bound flag, and a data path. Formatting may replace the display string later. It must not change the path.


6. Picture clauses

The display clause is format/picture. The picture under the ui element is the edit pattern and is not painted (Acrobat prints such a field as its raw value; this corrects the earlier reading). Alternates split on a vertical bar. The first alternate that accepts the raw value wins. A quoted alternate is a literal and always accepts.

date accepts canonical YYYY-MM-DD. time accepts hh:mm:ss. num accepts a canonical number with a period decimal and no grouping. text accepts any string. null accepts only null. zero accepts numeric zero. Reduced date symbols are YYYY, YY, MMMM, MMM, MM, DD, D, JJJ. Time symbols are HH, hh, MM, SS, A. Numeric symbols are 9, z, Z, period, comma, percent, and dollar. Text symbols are A, 9, and X; other characters are literal.

Locale month names and separators come from localeSet, else en_US. The canonical decimal point on input stays a period. Unsupported symbols paint the raw string. A clause that matches nothing paints the raw string. null with no null alternate paints empty. Inside null{} and zero{} bodies, quoted text is literal and an unquoted * is a digit placeholder painted as a space (Acrobat prints null{*******-**} as blanks around the hyphen). Numeric zero with no zero alternate uses the numeric alternate.


7. Field chrome

Chrome paints after layout and before text. Edges are top, right, bottom, left. One edge broadcasts. An edge with no thickness is 0.5pt; with no color it is black. A missing border element, on a field or a draw, paints no stroke. The visible box of most Designer fields comes from the border inside the ui widget (ui/textEdit/border and similar), so read both the field border and the ui border. A single corner radius applies to all four, but only when the corner's join is round; with the default square join the radius is ignored (pdf.js; Acrobat prints agree). Fill is solid, or a gradient: a linear or radial fill is a PDF axial or radial shading from the fill colour (white by default) to the gradient's own colour (black by default), clipped to the box. linear toRight (the default) starts at the left edge, toLeft at the right, toBottom at the top, toTop at the bottom; radial toEdge (the default) starts at the centre and reaches the end colour at the corners, toCenter the other way round (anaf-d093's toLeft section headings fade from grey at the left to white, as Reader prints them). A pattern fill paints the fill colour, then lines in the pattern's colour (black by default), 1pt wide every 4pt, clipped to the box: horizontal, vertical, diagonalLeft (rising to the left), diagonalRight (rising to the right), crossHatch (horizontal and vertical, the default) or crossDiagonal (both diagonals). A stipple paints the fill colour blended with the stipple's colour (black by default) at its rate (50% by default). A uniform lowered or raised edge is drawn inside the box: a band of the edge thickness in the edge colour, then a bevel band of the same width (lowered: 128 grey top and left, 212,208,200 bottom and right; raised: white, then 128 grey), as the Acrobat prints show. A uniform etched edge is a groove and an embossed one a ridge, as CSS (and pdf.js) draws them: the edge's thickness in two bands, etched outer grey (128) at the top and left and white at the bottom and right, inner the other way round, embossed reversed (adobe-master-pages-test's etched buttons print as such grooves in Reader). Rounded or mixed edges of these styles paint solid.

Caption placement is left (default), right, top, bottom, or inline. reserve is the strip removed before the value rectangle is built. An omitted, zero or negative reserve means the caption's measured width (left, right, inline), at most the content width, so a long caption wraps inside the field and the field grows (dclUnica 2025's two-line button), or measured height (top, bottom). Comb cells split the value rectangle, not the whole field; textEdit and numericEdit both take a comb.

textEdit paints the string; multiLine may wrap. numeric and date fields paint the picture-clause result. password paints one star per raw character. checkButton paints a square box of checkButton@size (default 10pt) and a mark when the raw value equals the on value. The default mark is a cross for a square box (thin strokes 15% in from the corners: the Reader prints of pdfjs-button-widget, anaf-d093 and ALTMP) and a dot for a round one. The on value is the first entry of items, the off value the second, an optional third is neutral. With no items, treat 1 as on (pdf.js also accepts the literal on). The box aligns by para hAlign; with none set it sits at the left of the value rectangle when the field has a caption and at the right when it has none (measured against Acrobat-generated static pages). choiceList paints the display item for the save value, or the raw value if none matches. Two items lists are save, then display. One list is both. exclGroup marks the matching member only. imageEdit uses the draw image rules. signature paints a label, not a glyph.

A barcode field (ui barcode) prints its symbol in the value rectangle, black on nothing (on white over a static shell page, so a design-time placeholder does not show). The payload is the raw value after scripts, not the formatted one, as bytes in charEncoding: UTF-8 by default, ISO-8859-1 (or none) one byte a character, UTF-16 big-endian with no byte-order mark; another encoding is logged and UTF-8 used. dataPrep flateCompress wraps the bytes in a zlib stream (RFC 1950, the deflate a CompressionStream makes) and PDF417 then encodes them in byte compaction. dataLength is a validation limit: Reader neither pads nor cuts the value (pdfium-barcodes' dataLength 100 symbols hold "1234567890"). An empty value prints nothing (XFA_BARCODE_EMPTY); an unknown type (code49, telepen, fim…) prints nothing (XFA_BARCODE_UNSUPPORTED). postUSIMB is the USPS Intelligent Mail barcode (USPS-B-3200): a 20-digit tracking code and a 0, 5, 9 or 11-digit routing code (after a hyphen, or run on) as 65 four-state bars, drawn as RM4SCC's are (its Figure 5 symbol as printed there). maxicode is a MaxiCode symbol (ISO/IEC 16023): Mode 2 or 3 when the value is a structured carrier message ([)>␞01␝yy, then the postal code, the 3-digit country and the 3-digit service class separated by ␝; a numeric postal code is Mode 2, another Mode 3), its primary message those three and its secondary message the rest after the header; else Mode 4. Text is compacted in code sets A to E with the fewest codewords (latches, shifts and nine-digit numeric runs), padded, and protected by Reed-Solomon over GF(64) (10 primary error codewords, 40 secondary in two interleaved halves). The 33 rows of hexagonal modules, every other row half a module in and one shorter, and the bullseye of three dark rings 9 modules across are drawn as large as the field allows up to the nominal 28.14 mm width, centred (zint and ISO/IEC 16023's Figure 2 symbol, read back by ZXing). aztec is an Aztec Code symbol (ISO/IEC 24778): the bytes in the fewest bits over the Upper, Lower, Mixed, Punct and Digit modes (latches, shifts, the CR LF, ". ", ", " and ": " pairs) and binary shift for the rest, in the smallest compact (1 to 4 layers, 15 to 27 modules) or full-range (1 to 32 layers, 19 to 151 modules) symbol whose error correction is at least 23% of its codewords plus 3; errorCorrectionLevel 0, 1, 2, 3 (or more) asks for 10%, 23%, 36%, 50%. Codewords are bit-stuffed, protected by Reed-Solomon over GF(2^6), GF(2^8), GF(2^10) or GF(2^12) by layer count, and laid in the spiral round the bullseye with the mode message (and a full-range symbol's reference grid). Its modules are sized and placed as the other matrix symbols' (below), and match zint's test symbols module for module (read back by ZXing); too much data for a 32-layer symbol prints nothing (XFA_BARCODE_DATA). The other linear types follow their published tables, filling the width as Code 39 does: Codabar (startChar and endChar A–D, A by default; checksum 1mod16 or auto adds the mod 16 character), code2Of5Interleaved (digit pairs, a leading 0 for an odd count, start nnnn and stop wnn) and code2Of5Industrial or code2Of5Standard (five bars a digit), code2Of5Matrix (each digit's five elements bar, space, bar, space, bar and a narrow space; start and stop open with a bar one module wider than a wide one, zint's 4X), each with a mod 10 check (weights 3 and 1) when checksum is 1mod10 or auto, Code 93 (check characters C and K), Code 11 (C, and K from ten digits; none when checksum is none), MSI and Plessey (Luhn check), EAN-13, EAN-8 and UPC-A (guards and parity, the check digit added to the 12, 7 or 11 digits; fewer are padded with zeros), UPC-E (six digits, number system 0, or seven); ean13add2, ean13add5, ean8add2, ean8add5, upcAadd2, upcAadd5, upcEadd2 and upcEadd5 are those symbols with a 2 or 5-digit add-on (the value's digits, the main symbol's then the add-on's, "+" or a space between them or else the last 2 or 5 digits the add-on; start 112, L and G codes by the value mod 4 or by the digits weighted 3 and 9 mod 10, 11 between digits) 9 modules after UPC-A and 7 after the others, its digits printed above it and its bars that text line shorter (with textLocation above, the line above the symbol already holds them), and upcean2 and upcean5 the add-on alone; logmars (Code 39 with its mod 43 check). wideNarrowRatio sets their wide elements (3 by default; MSI 2). The postal types are bars of one width with equal gaps across the field: POSTNET (postUSStandard, postUS5Zip, postUSDPBC; a mod 10 check digit, framing bars) tall bars the full height and short ones its lower 40%; RM4SCC (postUKRM4SCC; its row and column check character, an ascender to start and a full bar to stop) full bars, ascenders from the top to two thirds down, descenders from one third down to the bottom and trackers the middle third; Australia Post (postAUSStandard FCC 11 and postAUSReplyPaid FCC 45, 37 bars; postAUSCust2 FCC 59, 52 bars; postAUSCust3 FCC 62, 67 bars) drawn the same way: a start pair, the FCC and the value's first 8 digits (the DPID; fewer are padded with zeros) two bars a digit, then for Customer Barcodes 2 and 3 the rest of the value as customer information, two bars a digit when it is all digits (8 or 15 at most) else three bars a character of A-Z a-z 0-9 space # (5 or 10 at most; more is cut, XFA_BARCODE_DATA), tracker fillers, four Reed-Solomon check symbols over GF(64) of the bars taken three at a time, and a stop pair (zint's test symbols, among them the specification's Diagram 1). GS1 DataBar (ISO/IEC 24724) takes a GTIN for rss14, rss14Truncated, rss14Stacked, rss14StackedOmni and rss14Limited: 13 digits (the check digit added) or 14 (a wrong check digit is logged and recomputed), "(01)" before them allowed, fewer padded with zeros; Limited only a GTIN opening with 0 or 1. rss14 and rss14Truncated are the same 96-module row (the field's height makes it truncated), rss14Limited 79 modules, both filling the width as Code 39 does with their "(01)" GTIN-14 as text; rss14Stacked is two 50-module rows 5 and 7 high with a separator row, rss14StackedOmni two rows of equal height with three separator rows, both filling the width, separator rows one module high (less when the field is lower than the nominal height) and the other rows sharing the rest in proportion, no text. rss14Expanded takes GS1 element strings, "(01)98898765432106(3202)012345" (or [ ]; FNC1 after an AI without a predefined length), or the element string as it is: a compressed field for (01) (methods 1 to 14: weights (310x, 320x), dates (11, 13, 15, 17) and prices (392x, 393x)), the rest in the general-purpose field's numeric, alphanumeric and ISO 646 modes, 12 bits a symbol character, up to 21, in pairs round finder patterns on one row, its text the value with ( ) (zint's test symbols, among them the GS1 General Specifications' figures, read back by ZXing). Reader does not draw every type (the reader-tests barcodes print): aztec, rss14, rss14Truncated, rss14Stacked, rss14StackedOmni, rss14Limited, rss14Expanded, upcean2 and upcean5 print as the field's value rectangle filled 50% grey and edged in a 0.5pt black line; ean13add2, ean13add5, ean8add2, ean8add5, upcAadd2, upcAadd5, upcEadd2 and upcEadd5 fields print nothing and take no room, as a hidden field (their labels in the print stand 26pt apart, label and gap with no field between); that is the default, and flattenXfa(input, { barcodes: 'all' }) draws their symbols as described here (XFA_BARCODE_READER logs which). An Australia Post symbol prints at Reader's fixed size from the value rectangle's top-left, whatever the field's size: bars 1.559pt wide every 3.118pt, the tracker 4.08pt high with ascenders and descenders 5.1pt past it (full bars 14.28pt), and the value under it in the field font, centred on the symbol, its baseline 1.5 font sizes (12pt at 8pt) below the bars. A caption above or below a barcode prints just outside the field, the symbol taking the whole field inside its margins (echr-application-es's PDF417 and the reference line under it). Types are case-insensitive.

Code 39 (code3Of9; code3Of9extended maps each ASCII byte to its full-ASCII pair) upper-cases letters and skips characters outside 0-9 A-Z - . space $ / + % (XFA_BARCODE_CHAR); start and stop are *, or startChar and endChar when those are Code 39 characters; checksum auto (or 1mod43) adds the Mod 43 character before the stop, and printCheckDigit shows it in the text. A wide element is wideNarrowRatio narrow ones ("3:1", "3.0"; between 2 and 3, default 3) and characters are one narrow space apart. Code 128 (code128) starts in C for four or more leading digits (or an all-digit even value) and otherwise in B (A for a control character), and switches to C for six digits or more, or four at the end, an odd digit going first in the current set (ISO/IEC 15417 Annex E); code128A/B/C keep one set; ucc128 and ucc128sscc put FNC1 after the start; bytes 128-255 go behind FNC4; the mod 103 check value is always added. A 1D symbol fills the rectangle's width, with no quiet zone: Reader's print of mn-dhs-4258a puts the Code 39 bars of DHS-4258A-ENG exactly across its 63.5mm field, its modules wider than the 0.25mm default. Bars take the height (moduleHeight when set and smaller); textLocation (default below) adds one line of the field font above or below them, centred, or over them on white for the embedded positions, and none leaves it out.

PDF417 opens its data with a text latch (900) even though text is the default mode, then compacts as ISO/IEC 15438 does: text (alpha, lower, mixed and punctuation submodes, pairs of values in one codeword, an odd one padded with 29), numeric for 13 digits or more (base 900, 44 digits a group), byte for what is not text (901, or 924 for whole groups of six; 913 for a single byte in text). errorCorrectionLevel (default 0) gives 2^(level+1) Reed-Solomon codewords over GF(929) from ∏(x − 3^i). The columns are dataColumnCount, else as many as fit the width at moduleWidth with two modules of quiet zone each side; the rows are dataRowCount, else the fewest that hold the length descriptor, data and error codewords (at least 3, padding with 900). Row indicators follow ISO/IEC 15438: for row r, cluster r mod 3, 30·⌊r/3⌋ plus (rows−1)/3, level·3 + (rows−1) mod 3 or columns−1 by cluster. moduleHeight is not used: the rows share the height left after two modules of quiet zone above and below. truncate leaves out the right row indicator and the stop pattern. QR Code (qrcode) is model 2 in one segment (numeric, alphanumeric, else byte) and the smallest version at its level; errorCorrectionLevel 0 is L, 1 M, 2 Q, 3 or more H, absent M, and the level is not raised to fill the version. Of the eight masks Reader picks the lowest score of runs of five or more (3 plus the excess), 2×2 blocks (3 each) and the dark share (10 per 5% from half), without the finder-like pattern rule; pdfium-barcodes' QR is mask 3, which only that score picks. Data Matrix (dataMatrix) is ECC 200 in ASCII encodation (digit pairs in one codeword, upper shift for bytes over 127) in the smallest square symbol, Reed-Solomon over GF(256) (0x12D) in interleaved blocks, placed by ISO/IEC 16022 Annex F. A 2D symbol's modules are moduleWidth wide (0.25mm when absent) and square, except PDF417's rows; four modules of quiet zone surround a QR symbol, one a Data Matrix symbol and two an Aztec symbol; the symbol is centred and, when it does not fit, its modules are narrowed until it does. Reader prints 2D symbols as 300 dpi images, so module widths round to whole 1/300 inch pixels and row heights are cut down to them (0.338mm modules are 4 pixels; echr-application-es's PDF417 rows 66). Modules are filled rectangles, one per run of dark modules on a row. With these rules pdfium-barcodes' PDF417 and QR symbols are Reader's, module for module.


8. Draws

A field of any kind whose (template) value is an embedded image shows the image, as an imageEdit field does (pdfium-png-image's text field holding a PNG).
A draw is boilerplate and does not bind. text and exData go to typography. rectangle uses the border. line strokes the box on the named slope. arc strokes an elliptical curve (circular when circular="1"); omitted sweep is 360 degrees. Its fill closes with the chord between the curve's ends, not through the centre (Reader's print of pdf.js issue 14315: filled quarter arcs are segments). image href resolves inside the template packet, as a data URI, or by name in the PDF's /Names /XFAImages name tree, which holds image files keyed by their href (itext-dataset-2page's ".\Resources\…png" logos; pdf.js reads it too). Any other href (a file or URL beside the form) is loaded through the caller's images(href) option when there is one, else paints nothing. fit scales proportionally and sits at the top-left of the box unless para hAlign/vAlign say otherwise (Acrobat prints; pdf.js centres it), none stretches, actual paints intrinsic size from the top-left and clips. Shell PDF images are not consulted.


A signature field (ui signature) paints its border and caption and no glyph, as Reader prints one unsigned. A signed one on a dynamic form, whose pages are made anew, prints the appearance of the AcroForm signature widget of the same name ([0] indexes and #subform levels aside) that has a value: the widget's normal appearance is fitted to the field's laid-out rectangle as a widget's is to its /Rect (§12); a static form keeps its widgets' appearances already (§9).


9. Static versus dynamic

NeedsRendering true means dynamic. dynamicRender required, or a bound occur that emitted more instances than the prototype, are secondary signals. Otherwise the file is static. (pdf.js keys XFA rendering on NeedsRendering alone and shows static files from their shell pages and widgets.)

Dynamic pages are synthesized from the page area. Do not copy shell content. Static pages keep the shell content stream. Paint only the display string and the check mark, with a white fill behind the string so the design-time placeholder is covered. Do not repaint borders or draws, with one exception: a comb field's widget box and cell dividers live only in its widget appearance, which is dropped, so they are painted in the field's own style (Reader draws them: the Anexa and D212 CNP fields), but only where the shell page has a comb text widget (Ff Comb, MaxLen) over the field, since a static template's page subforms need not match the shell pages one to one. More generally, each field is matched to the widget the shell page was saved with (its AcroForm name, "[0]" indices and the class of nameless containers dropped: "form1[0].#subform[0].f[0]" is form1.#.f); where the widget's rectangle disagrees with the template's value rectangle (a check box's box) by more than a point, Reader drew the widget, so the widget's own appearance is stamped when it has one and otherwise the value (or check mark) is painted in the widget's rectangle. The template still lays out everything else. Widget appearances are not flattened in general; they also hold on-screen buttons that Reader does not print. A static file with empty shell pages is treated as dynamic.

Both classes drop XFA, NeedsRendering, and the AcroForm field dictionary on output.


10. Measurement

Width is the substituted face, not the requested face, times horizontal scale, plus letter spacing after every glyph but the last. Vertical scale does not change width. Break on spaces, and after a slash that is not followed by a digit or another slash (Unicode line breaking: Acrobat prints break imm0157f's "he/ she" and a registration form's "(https:// www.ontariopid.com…"); hyphens are not break opportunities. A line may overrun its width by 0.05em before it breaks (Acrobat fits evince's title 0.018pt over, Stammdatenaenderung's "Änderungen aus." 0.022pt over and on-11075e's 9pt Arial ", am the" 0.40pt over, and breaks imm5707e's 8pt Arial "If you" 0.46pt over; Myriad lines fit up to about 0.5pt over in the prints). A token wider than the rectangle is one clipped line. Do not hyphenate. The em box for baseline and middle alignment is the substituted face at size times vertical scale. Do not stretch a run to imitate the missing face's advances. Log the substitute once per face per document.


11. Scripts

Scripts run after binding and after the saved form state (§1) is restored, as Acrobat restores it when the form opens and runs its print scripts later (hmrc-c1800-chief's prePrint shows every section the saved state had hidden), so what they decide reaches formatting and layout. Each fires once, in the order Acrobat fires them when a form is opened and printed: initialize for every object in document order, a container before its children (hmrc-c1800-chief's root initialize sets up the Styles script object its children read); calculate scripts in document order, twice, so a total over later fields settles; ready with ref $form; ready with ref $layout (run before layout, as if layout were done: layout queries such as xfa.layout.page fail, and page-number scripts stay with painting); docReady; prePrint (the Reader prints are prints). A table row that prePrint hides keeps its height, as if invisible (mn-dhs-4258a's add-row footers leave their gap under the table in Reader's print); other containers it hides close up (hmrc-c1800-chief's help text). User events (click, change, enter, exit, mouse, submit) never fire on their own; execEvent, execInitialize and execCalculate run them on request, nested at most eight deep. A calculate script's value becomes the field's value; JavaScript's undefined leaves it unchanged.

FormCalc (XFA 3.3 §25) and JavaScript (the ES3/ES5 that Acrobat runs) are both interpreted from a parse tree. Form code is never handed to the host engine: no eval, no Function. Member access goes through an allow-list of string, number, array, date and regular-expression methods, of objects the script made itself (null prototype, so constructor and __proto__ lead nowhere), and of the XFA object model. A step budget and a call-depth limit stop runaway scripts. A script that fails, or that asks for something the object model lacks (adding subform instances, layout queries), stops there, keeps what it already did and is logged; the next script runs regardless.

Names resolve as in Acrobat. Local variables come first, then (JavaScript) the document's globals, built-ins and undeclared assignments shared by all scripts. Then SOM scoping applies: the children of the script's object, then of each ancestor in turn, seeing through nameless subforms, areas, subform sets, exclusion groups and page sets (pdf.js searchNode). Page sets come after an object's content, so form1.Page1 is the subform Page1 and not a page area of the same name (Conflict-of-interest, imm1294e). Script objects (<variables><script name>) are children of their subform too, and answer node methods (resolveNode, resolveNodes) for that subform. A script object that stops while loading keeps what it defined (its functions are hoisted). A function called plainly runs with this as the object its script belongs to. Properties a script sets on an XFA object that are not XFA properties stay on it, as on Acrobat's JavaScript wrappers (form1.hidePagesExcept = function …). Function prototypes have a constructor, and objects made by new keep their prototype chain, so classic inheritance helpers work; fn.arguments is the running call's arguments. #class steps (#items, #text) and property objects (caption.value) resolve in SOM strings; access is modelled (a form's "is it blank?" check skips read-only fields); ui.oneOfChild.className is the widget; border.edge and border.corner presence, colour and thickness can be set (one edge given covers every side), by script or by the saved form state. E4X attribute steps (node.@name) parse, though XML objects are not modelled. xfa.resolveNode(s) resolves from the xfa root, and an unqualified name not found there from the object whose script is running (hmrc-iform hides its wizard pages with xfa.resolveNodes("MainFormPage[*]")). A field is a page-number field only when a script assigns its rawValue from xfa.layout.page/sheet(this) or pageCount/sheetCount(); a script that merely tests a layout query runs like any other (hmrc-iform's form title). Each runs once on first use, and its top-level variables and functions are its properties (Attestation's IDocs.Debug, Purchase.Order's countryScript). _name is the instance manager of the subforms called name, even with no instances. The shortcuts are $, $record, $data, $form, $host, $layout, $event, xfa and !. On the data side, attributes are named children (dataValues) after the elements: Attestation reads $record.FrgBoutons.watermark1.presence.value, an attribute.

fillColor reads the border fill (white without one) and sets it, giving a fill-only border to an object that has none; the saved form state restores border fills the same way (itext-release-objects saves its page subform red and its docReady script turns red into blue, Reader's solid blue page). Scripts may set keep.intact, keep.next and keep.previous (hmrc-c1800-chief's prePrint scripts keep each section whole, so its Badge details section starts page 2 in Reader). A layout:ready script of page-area boilerplate that asks for its page (xfa.layout.page, pageCount, sheet…) is not run before layout but once per page after it, with those queries answered; what it hides is not painted on that page (hmrc-c1800-chief prints its form number on page 1 only), and the value it gives its field is printed on that page alone (lu-resa-listing's footers read Page 1 / 71, Page 2 / 71…). Other layout queries are answered from a first layout of the form: page(node) (from 1), absPage(node) and sheet(node) (from 0), pageCount, absPageCount and sheetCount, pageSpan(node), h, w, x and y(node, unit) (in inches unless a unit is given: in, cm, mm, pt; x and y on the page) and pageContent(index, className); when a script asked one, the form is bound, scripted and laid out again from fresh packets with those answers (XFA_RELAYOUT), as Acrobat runs layout:ready scripts on its finished layout (lu-resa-listing's summary shows the page of each letter's first entry). Before that, page() answers 1, pageCount() 1 and sizes 0; layout.ready is true on the second pass. A script changes only what prints: presence, relevant, rawValue, formattedValue (kept as the display text), x, y, w, h, choice-list items, caption text and presence, draw text, font (typeface, size, weight, posture, colour, fontColor), border presence and fill colour, margins, keeps and paragraph alignment. Other properties read as empty and ignore writes. xfa.host is Acrobat Reader with no dialogs: messageBox returns 1. Date() and new Date() are the time of flattening, or a time the caller passes in.

FormCalc values are numbers, strings and null. Keywords and function names are case-insensitive. Comparing two strings is a string comparison; any other comparison is numeric. null equals only null, "" and 0. Arithmetic on two nulls is null and one null counts as 0: Purchase.Order's Amount stays blank when quantity and price are empty, as in Reader. A field used as a value is its rawValue: null when empty, a number when the field is numeric. The built-ins cover arithmetic (Abs, Avg, Ceil, Count, Floor, Max, Min, Mod, Round, Sum), dates (Date, Date2Num, DateFmt, IsoDate2Num, Num2Date, Time), logic (Choose, Exists, HasValue, Null, Oneof, Within) and strings (At, Concat, Format, Left, Len, Lower, Ltrim, Replace, Right, Rtrim, Space, Str, Stuff, Substr, Upper). Num2Date formats with the picture clauses of §6 in the field's locale. Attestation's "Fait à …, le" date prints as "2 octobre 2026" from Num2Date(Date(), "D MMMM YYYY") in fr_BE.

A script may change how many instances of a subform there are, before layout: the instance manager (_Row, Row.instanceManager) adds one with addInstance(merge), bound with merge (the default) to the next unbound data element of that name under the parent's data, or to a new empty element appended there, and without merge to nothing; removeInstance(i) (the last when omitted) takes one out, with any data element it added, and renumbers the later ones (index and SOM, down their subtrees: Row[1] is then the old third row); setInstances(n) and count = n add or remove until n. Counts stop at occur max (−1: no limit) and min without an error; a further addInstance returns the last instance. A new instance goes after the last of its name, else where the template puts it; it joins the scripted objects there, runs its initialize before addInstance returns (the caller's writes come after), and the calculate passes that follow include it. insertInstance(i, merge) adds one at position i among them, its new data element before the one of the instance it precedes, and renumbers those after; moveInstance(from, to) moves one to another position, its data element with it, and renumbers. Adding to page-area boilerplate fails. A name is found through nameless containers and through areas, named or not (dclUnica's Cap1.G2 scripts read G11.I11 and Cap1.G12.I12, held by the area G1, and reach Cap2.G1.G11 by its name too).

A <variables> <manifest> is a named list of SOM references; its evaluate() returns the objects they resolve to, in order, leaving out any that do not resolve. A reference may escape a dot in a name ("AreaLeft_A\.1"). A field's or radio group's dataNode is its data value as Acrobat's merge would make it, whether or not the file holds data: named as the field, its value the field's raw value ("" when empty; a radio group with no button on is empty, even when its buttons hold an off value such as "Off"), its somExpression under xfa[0].datasets[0].data[0]. A form without data still has xfa.datasets.data, an empty data group. After prePrint the calculations run once more, as Acrobat recalculates what a print script changed: a paper forms barcode's prePrint joins its manifest's values with its delimiter into a hidden field and the barcode's calculate copies it (echr-application-es prints Reader's "SPA - 2016/1|||…|0|||…" symbol).

12. AcroForm (no XFA)

A PDF without XFA is flattened through its AcroForm: the pages are copied as they are and every printable annotation is stamped onto its page from its normal appearance, after the page's own content, in /Annots order. The field tree under /AcroForm /Fields is walked with its inheritable attributes (FT, Ff, V, DV, DA, Q, MaxLen, Opt, TI, I). A widget prints on the page its /P names, else on the page whose /Annots lists it; a widget only a page lists takes its attributes up its /Parent chain. An annotation prints when its Print flag (4) is set and its Hidden flag (2) is not, as Reader prints. The normal appearance is /AP /N, or for a dictionary of states the stream /AS names (a check box's /Yes or /Off). It is drawn as a form XObject: its BBox, transformed by its Matrix, is scaled and moved onto /Rect (PDF 32000 §12.5.5). Other annotations with an appearance (highlights, ink, shapes, stamps, free text) print the same way; popups never do. A widget with no appearance is generated, and so is every text and choice field's when the AcroForm sets /NeedAppearances, and then a button's that has no appearance for its state (a radio button whose /AP /N lacks /Off); other button appearances are kept. A push button with no caption or icon prints its background and border alone. A text or choice field with no /DA, its own or the AcroForm's, prints its background and border without its value, as Reader does. The rectangle is fixed. /MK /R turns the content by 90, 180 or 270 degrees. /MK /BG fills the box; /MK /BC strokes the border at /BS /W (else /Border, else 1) in the /BS /S style: solid, dashed (/D), beveled (white top-left, half the background bottom-right), inset (grey 0.5 top-left, 0.75 bottom-right) or underline; radio buttons in the circle style (/MK /CA l, the default) are round, in the other styles square, as Reader draws them. Text sits inside the border (twice its width for beveled and inset) and 2pt in from the sides, in the /DA font, size and colour (the widget's, else the AcroForm's); the font is the /DR font of that name, its BaseFont read as family and style ("Arial-BoldMT" is Arial bold) and drawn as XFA text is (§4), or one of the conventional names (Helv, TiRo, Cour, ZaDb). /Q aligns left, centre or right. One line is centred vertically; size 0 fits it to the box, at most 12pt and at least 4pt. A multiline field (Ff bit 13) wraps from the top at the face's line height, size 0 taking the largest size up to 12pt whose lines fit. A comb field (Ff bit 25 with MaxLen) splits the full width into MaxLen cells and centres one character in each. A password field shows asterisks. A combo box shows the /Opt label of its value; a list box its options from /TI, the selected ones (/I, else /V) on a light blue band (0.6, 0.757, 0.855). A rich text field (Ff bit 26) shows its plain /V in the /DA font like any text field: Reader generates it from /V, not from the rich text value (/RV) or /DS (the reader-tests fields print). A line holding right-to-left text is laid out left to right with its right-to-left runs reversed in place (the Unicode bidirectional algorithm at paragraph level 0): Reader prints "שלום עולם (test)" with the Hebrew at the left, then "(test)". A push button with an icon (/MK /I, a form XObject) places it by /MK /TP: 0 caption only, 1 icon only, 2 caption below the icon, 3 above it, 4 to its right, 5 to its left, 6 over it; the caption takes a line (its text width plus 2pt a side for 4 and 5) and the icon the rest, fitted by /MK /IF: /SW scales always (A, the default), only when bigger (B) or smaller (S) than its space, or never (N); /S P keeps proportions, A stretches; /A places the leftover space (0.5 0.5, centred); /FB true fits the whole rectangle, border included. An unsigned signature field with no appearance prints its background and border. A check box or radio button that is on (/AS, else /V, not Off) shows its /MK /CA ZapfDingbats mark as a shape in the /DA colour: check (4, the check box default), circle (l, the radio default), cross (8), diamond (u), square (n) or star (H), sized to 80% of the box or to a non-zero /DA size. The output has no AcroForm and no annotations, so no viewer paints a field twice. A PDF with no form at all is copied unchanged. flattenXfa(input, { xfa: false }) takes this path even when the file carries XFA.

Fonts the pages use without embedding them (on AcroForm pages and static XFA shell pages alike) print as Acrobat prints them, with a substitute stretched to the font's widths. Each becomes an embedded TrueType program of its own, one glyph per code, every glyph scaled horizontally to the width the font declares (clamped to 0.6–1.6 and centred beyond that), from Liberation Mono for monospaced fonts (FixedPitch, or Courier, Consolas… in the name), Liberation Serif for serif ones (Times, Georgia, Garamond… in the name, else the Serif flag), else Liberation Sans or Source Sans Pro, whichever is closer in proportion to the declared widths of letters and digits; bold (ForceBold, FontWeight 600 or more, Bold/Black/Semibold in the name) and italic (Italic flag, an italic angle, Italic/Oblique in the name) pick the style. A simple font (Type1, MMType1, TrueType) reads each code's character from its glyph name (/Encoding over its base encoding, StandardEncoding for Type 1 and WinAnsiEncoding for TrueType by default, and /Differences), else from /ToUnicode; it becomes a symbolic TrueType font addressed by code, with its /FirstChar and /Widths (none: the substitute's own) and a /ToUnicode. A Type0 font with Identity-H or -V and a TrueType CIDFont reads each CID's character from /ToUnicode (the name /Identity-H makes each CID its own Unicode value, for the CIDs its /CIDToGIDMap or /W names), or without one as a glyph number in the Windows core fonts' glyph order (Arial, Times New Roman, Courier New, Verdana, Tahoma, Calibri, Trebuchet MS…, through /CIDToGIDMap when present); the CIDFont gets the program and a /CIDToGIDMap, keeping /W and /DW. A Chinese, Japanese or Korean font, which Reader draws with its own CJK fonts and viewers without them do not draw at all, is substituted when a CJK TrueType font is supplied (fonts/CJK.ttf, or load('CJK')): a Type0 font with a predefined CMap (the Shift-JIS, EUC, raw JIS, GBK, GB 18030, Big5, EUC-KR/UHC and Unicode UCS-2, UTF-16, UTF-8 and UTF-32 ones, horizontal or vertical) gets an embedded CMap with the predefined one's code space ranges, so the strings keep their bytes; the codes the pages show (in their content, the form XObjects they draw and their annotations' appearances) each get a CID and the CJK font's glyph for the character the CMap's encoding gives (decoded with the platform's TextDecoder; no CMap files are needed), at the font's widths (a Japanese single byte's half-width CID's /W, else /DW: with no /W Reader advances the single bytes of "(57)" and a Korean space a full em, as the reader-tests print shows), centred and not stretched, with a /ToUnicode. A Type0 font with Identity-H or -V and a /ToUnicode, CFF-based (CIDFontType0) or TrueType, takes its CJK characters from the CJK font in the same way. Without a CJK font these are left as they are, logged as FONT_CJK_NOT_EMBEDDED. The standard 14 fonts, symbol fonts (Wingdings, Symbol, Dingbats…), fonts named in another script (whose single bytes Reader does not read as CJK either) and CID fonts with other encodings are left as they are.

A comment or markup annotation with no appearance is drawn from its dictionary, as a viewer generates it, in /Annots order with the rest; /CA is its opacity throughout. Colours are /C (stroke, or fill for highlights, carets and notes) and /IC (interior fill); the border width is /BS /W, else /Border's third entry, else 1, dashed by /BS /D when /BS /S is /D. Highlight: each quadrilateral of /QuadPoints (top-left, top-right, bottom-left, bottom-right; the rectangle when there are none) filled in /C, yellow by default, with the Multiply blend mode. Underline, StrikeOut and Squiggly are sized by each quadrilateral's height h, as Reader prints them (measured on PDFium's annotation_markup_multiline_no_ap): Underline a line h/14 wide, 0.15h up from the bottom edge; StrikeOut the same 0.44h up, between points that far up its left and right edges; Squiggly a zig-zag h/50 wide along the bottom edge, from h/16 to 3h/16 up, in steps of h/8. Line: /L in /C at the border width (1 when 0); /LE endings, six times the line width: OpenArrow and ClosedArrow (30 degrees either side, pointing out), their reversed forms, Square, Circle, Diamond (that size across), Butt (a perpendicular), Slash (30 degrees from the perpendicular); closed endings filled in /IC. Square and Circle: the rectangle less /RD, the border drawn inside it, filled in /IC; none with no border and no fill. Polygon: /Vertices closed, filled in /IC; PolyLine: open, with /LE endings. Ink: each /InkList path joined by straight lines with round caps and joins; a single point is a dot. FreeText: /C fills the rectangle less /RD, the border is in the /DA colour, and /Contents wraps inside the border, 2pt in from the sides and 1pt from the top, in the /DA font and size (12pt when 0), /DS's color and size winning; /Q aligns it. A callout (/IT /FreeTextCallout) draws its /CL line, /LE's first ending at its start. Caret: a caret filled in /C. Text (a note): a 20pt sheet with a folded corner and ruled lines filled in /C at the rectangle's top-left (the rectangle's size when that is at least 10pt). Stamp: Reader's placeholder whatever its /Name and /C, the rectangle crossed corner to corner in black 1pt lines half a point inside it (the 14 standard stamps of the reader-tests annotations print). A cloudy border (/BE /S /C, intensity /I above 0) on a square, circle, polygon or free text replaces its straight path with Acrobat's curls (as PDFBox's CloudyBorder reproduces them, matched to the reader-tests print): circles of radius 4 × intensity + half the line width (4.75 × intensity + half the line width round an ellipse) centred on the path 2·cos 34° radii apart, each drawn as an arc from 12° past the backward direction, a tail inside the curl before, round the outside to 34° short of the forward direction, where it meets the next. Along a polygon each edge has a corner curl at its start and as many intermediate curls as fit, the corner's trailing arc and the first intermediate curl's leading arc adjusted so they fill the edge; round an ellipse (its rectangle less /RD, shrunk by sin 12° × radius − 1.5) the curls are spread evenly by length. A square's or free text's box is the rectangle less /RD, at least half the line width in from each side. A Polygon's /Vertices are an open path: the edge back to the first vertex is drawn straight and the first vertex has no corner curl, as Reader prints them. It is stroked and filled as the straight path would be, and a free text's text stays inside the uncurled box. File attachments, sounds and redactions with no appearance print nothing, and links never print. A free text's /Rotate is ignored.

An AcroForm's JavaScript runs as Acrobat runs it on opening and printing: the document scripts (/Names /JavaScript, in order; their top-level functions and variables are globals), then every field's format action (/AA /F) on its value, which leaves the value as it is and gives the text an appearance generated for it shows ("1234.5" with AFNumber_Format(2, 0, 0, 0, "$", true) is "$1,234.50"), then the open action, the first page's open action and the will-print action (/AA /WP). When those change a value, the calculation actions (/AA /C) run in the AcroForm's /CO order, each result becoming its field's value, and every changed field is formatted again; with no change, no calculation runs (Acrobat does not recalculate on opening). Keystroke and validate actions do not run. A text field whose value a script changed gets a new appearance; a check box or radio button whose state changed prints its appearance for that state; display (visible, hidden, noPrint, noView) and hidden set the widget's Print and Hidden flags; textColor, fillColor and borderColor give generated appearances their colours (AFNumber_Format's red negatives). The object model: this is the document (getField, by full name or a parent name whose getArray lists its fields; getNthFieldName, numFields, calculateNow, calculate, numPages), event (target, value, rc, willCommit, name), fields (name, type, value, a number when its text is one; valueAsString, display, hidden, textColor, fillColor, borderColor, exportValues, isBoxChecked, checkThisBox, getItemAt, buttonGetCaption), color, display, util (printf with Acrobat's %,N separators, printd, printx, scand) and the AF functions (AFNumber_Format, AFPercent_Format, AFDate_FormatEx and AFDate_Format with Acrobat's 14 date formats, AFTime_Format, AFSpecial_Format for zip, zip+4, phone and social security numbers, AFSimple_Calculate, AFMakeNumber, AFParseDateEx); keystroke and validate functions accept. A failing script is logged and the next one runs.

Optional content (layers) prints as Reader prints it. A group's state comes from the default configuration (/D: BaseState, then its ON and OFF lists), then, for the groups its /AS array lists for the Print event, from each group's /Usage /Print /PrintState (a screen-only layer whose PrintState is OFF does not print; a print-only one whose PrintState is ON does). A membership dictionary (OCMD) prints by its /VE expression (And, Or, Not), else by its /P policy over its /OCGs (AnyOn by default). A group not listed in /OCProperties /OCGs prints. The output has no /OCProperties, so what does not print is taken out of the page: marked content from /OC /name BDC to its EMC (names from the stream's /Properties resources), each Do of an XObject whose /OC does not print, and each annotation whose /OC does not print; page content streams and form XObjects are filtered as they are copied, for static XFA pages too, whenever the document has layers (a membership expression such as /Not can hide content with every group on). Marked content of a group that prints becomes plain marked content (/JcsOC BMC), and a copied XObject loses its /OC: with no /OCProperties left, viewers would read a remaining group differently (PDFium evaluates a membership expression with every group on, poppler shows the content). A stream with a filter other than Flate, which this library does not decode, is copied whole and logged.

The document prints as Reader prints it. A PDF Portfolio (/Collection in the catalog) prints its PDF files, not its cover sheet: each embedded file (/Names /EmbeddedFiles, in name order) that is a PDF is flattened with the same options, and their pages follow one another; files that are not PDFs are skipped, and a portfolio with no PDF prints its own pages. A page with /UserUnit u is scaled to points: its MediaBox times u and its content drawn at u, so viewers that ignore UserUnit print it at its size too. The print preferences of /ViewerPreferences (PrintScaling, Duplex, PickTrayByPDFSize, NumCopies, PrintPageRange) are kept; the rest of the catalog is not.

Two options change what prints. annotations: false leaves out every annotation that is not a widget. labelFields replaces each field with its name: every widget not Hidden (printable or not) is replaced by its field's full name, or with name 'short' the last part without a [0] index; a button widget whose name other widgets share adds "=" and its on state (the /AP /N state that is not Off). On XFA forms the name is the field's SOM expression, each level indexed and a nameless container written #subform; it goes where the value would go (the widget's rectangle on a static form when that disagrees, §9), and the field's border and caption still print but not its value or ui border (a button is labelled across its whole box). The name is one line of Helvetica (the bundled face when fonts are embedded), 2pt in from the left when the box is wider than 10pt, centred vertically, at the largest size in quarter points from maxSize (12) down to minSize (5) that fits the box's height and width, in the given colour (red); a name too long at minSize is clipped at the box's sides but not above or below it. Widgets are turned by /MK /R as their content is.


Out of scope

Scripts beyond §11 (user events nobody fires), usehref fragments, external images nobody supplies, and bookends naming objects outside their container will not match Acrobat. Page selection beyond §3, subformSet choice, and a static file whose widget rectangles disagree with the template are the remaining unspecified cases. When the widget and the template disagree, the template box wins.

For mobile-readable output of ordinary Designer files, this is a complete spec.


Verification notes

Rules in this file were checked against the pdf.js XFA engine (mozilla/pdf.js, src/core/xfa, commit c33c32a, 2026-10-01). pdf.js renders XFA to HTML for viewing, so it is a reference for semantics, not for pixel output. Changes made after that check: Myriad and declared faces drawn with the best-fitting bundled glyphs (Source Sans Pro or Liberation Sans) instead of Liberation Sans only; x and y ignored in flowed layouts; inactive treated as hidden; relevant (-print) added (not printed, but keeps its space); position containers with omitted h grow to fit; occur defaults (min 1, max follows min); no default field border, edge thickness 0.5pt, ui widget border; caption reserve auto when omitted, inline placement; checkButton size and on/off items; NeedsRendering as the primary dynamic signal. Confirmed unchanged: default font Courier 10pt; bind match modes once, dataRef, global, none, default once. Open conflict: bare-number unit (Adobe spec inches, pdf.js points).
